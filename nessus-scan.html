Nessus Vulnerability Scan

Running authenticated vulnerability scans across five lab machines and reading the results by severity.

Goal

Use Nessus Essentials to scan every machine in the lab, then compare the findings to see how exposure differs between the managed Windows domain and a deliberately vulnerable target. The point isn't just to run a scan — it's to read the report and understand what it's telling me.

Setup

From my Parrot box I confirmed the Nessus service was running, found each target's IP on the lab segment with a quick nmap ping sweep, and ran a Basic Network Scan against all five. Host discovery doesn't count against the Essentials 16-host limit, so I used it to confirm every machine was up first.

What the numbers show

  • Metasploitable2 was the most exposed by far — 9 critical and 6 high findings — which is expected for an image built to be vulnerable.
  • DC02 and 00Seven, both older Windows builds, carried real critical findings, a reminder that unpatched legacy servers are where risk collects.
  • DC01, the newest server, had no criticals and only one high — the clearest illustration of why keeping systems current matters.
  • Some categories showed as "mixed," meaning a single plugin family returned more than one severity level.

Takeaway: a vulnerability scan is only useful once you can read it. Severity counts point you to what to fix first — criticals and highs on the oldest machines — and turn a wall of findings into a prioritized action list.
